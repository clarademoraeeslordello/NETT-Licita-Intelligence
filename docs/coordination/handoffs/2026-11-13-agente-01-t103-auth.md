- De: agente 01 · Para: todos · Data: 2026-11-13

- Decisão: ADR-005a (openid-client em vez de Auth.js v5 beta)

## O que foi feito
- `src/server/auth/`: config, fluxo OIDC (PKCE S256 + state + nonce em cookie JWE), sessões server-side (`sessions`, migration `0002`), provisionamento por `sub`, `authorizeCompany`, `requireSession`, `requireCompanyAccess`, `requireRealmRole`, `withApi` (erros → `apiError`, checagem de `Origin` em mutações).
- Rotas: `GET /api/auth/login?returnTo=`, `GET /api/auth/callback`, `POST /api/auth/logout`, `GET /api/v1/me`.
- Realm local: mapper `realm_roles` no ID token. **Quem já subiu a infra precisa recriar:** `docker compose down -v && npm run infra:up`.
- CI: job de banco agora sobe Keycloak e roda `test:auth:integration`; `test:auth` no job rápido.

## Como usar (agentes 02–04)
```ts
import { requireSession, requireCompanyAccess, withApi } from '@/server/auth';
export const GET = withApi(async (_req, { params }) => {
  const session = await requireSession();
  await requireCompanyAccess(session, (await params).cid, 'consultant');
  // ...
});
```
Nunca ler cookie de sessão diretamente nem confiar em `companyId` sem `requireCompanyAccess`.
