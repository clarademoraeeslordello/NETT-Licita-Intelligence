- `enqueue(name, payload)` tipado por `src/contracts/jobs.ts`; payload validado com Zod; `singletonKey` = payload serializado com chaves ordenadas; reenfileirar trabalho já na fila devolve o id existente.

**T-106 — `src/server/storage/index.ts`**
- `ObjectStorage` (`put`/`get`/`signedUrl`) sobre `@aws-sdk/client-s3` com `forcePathStyle`; `sha256` e tamanho devolvidos no `put`.
- Chaves aceitas somente `public/<uuid>/<sha256>[.ext]` e `companies/<uuid>/<uuid>[.ext]` (+ `.text/<n>.txt` para texto extraído); bloqueia `..`, barra inicial, outros prefixos.
- `signedUrl` limitado a 1–600 s. Authz fica na rota (T-203/T-204). Checksum só quando exigido (compatível SeaweedFS/Railway).

**T-201 — `src/server/sources/**`, `src/lib/pncp/**`**
- `SourceConnector` (CONTRACTS §5) e `PncpConnector` sobre `src/lib/pncp/client.ts` (cache, dedupe, retentativa) + disjuntor do `/consulta` extraído para `src/lib/pncp/disjuntor.ts` e compartilhado com `api.ts` (comportamento herdado mantido).
- `fetchPage(cursor)`: `/consulta/v1/contratacoes/atualizacao` (novas **e** alteradas), modalidade × dia, 50/página; cursor JSON versionado e retomável (página → modalidade → dia até `until`).
- `enrich(payload)`: itens (paginados) + arquivos. Separado de `fetchPage` para T-202 só enriquecer o que passar no filtro de SearchProfile (respeito ao limite do PNCP).
- `normalize(payload)` **puro** → `canonicalKey = pncp:<cnpj>-<ano>-<seq>`, decimais em string, UF/esfera/modalidade/status/benefício ME-EPP/SRP/sigilo, `contentHash` estável; documentos só com URL HTTPS de `pncp.gov.br` (base anti-SSRF para T-203).
- `PNCP_MIN_INTERVAL_MS` (opcional) espaça requisições no processo; padrão 0 = comportamento herdado da UI.
